# How to Activate a New Fixed-Month BOHO/D4 Book

**Last updated:** 2026-08-06

This is the operational reference for turning `Johansen_Template_Engine.xlsx` into a live book for a specific contract month (March, July, etc.). For the engineering/build-pipeline side (how the template is generated, known defects, how to fix them), see `docs/superpowers/HANDOFF.md` instead — this doc is "how do I use it," that one is "how does it work / what's still broken."


| File | Role |
|---|---|
| `Johansen_FM_BOHO_D4_Strategy.xlsx` | **Live December book. Never touch, never Save-As directly into a new month — read-only source.** |
| `Johansen_Template_Engine.xlsx` | **The master template.** Copy this to start a new month. Regenerated by `scripts/build_template.py` — don't hand-edit its engine formulas. |
| `Johansen_Template_Engine_validation_copy.xlsx`, `Johansen_FM_BOHO_D4_Strategy_dec_validation_copy.xlsx` | Throwaway scratch copies the validation script creates. Not part of the normal workflow — ignore. |

Build scripts live in `scripts/` (`build_template.py` is the orchestrator). You generally don't need to run these to activate a month — only if the underlying engine itself is being changed.

## 2. The template's 10 sheets, in order

`Notes → Config → Data → DiffLag → Matrices → Johansen → Johansen_Monthly → Monthly Beta → Position Model → Results`

**You only ever touch `Config` and `Data` directly, plus one recurring manual log entry on `Johansen_Monthly`.** Everything else (`DiffLag` through `Results`) recalculates automatically off those inputs — never hand-edit engine-sheet formulas in a live book; a structural fix belongs in the template scripts, not a one-off patch in an instantiated book.

## 3. Step-by-step: activating a new month

### Step 1 — Save As
Copy `Johansen_Template_Engine.xlsx`, rename it `Johansen_<Month>_BOHO_D4_Strategy.xlsx` (e.g. `Johansen_Mar_BOHO_D4_Strategy.xlsx`), save it in the same `BOHO Trading` folder.

### Step 2 — Fill in the `Config` sheet
Column A holds the defined-name labels, column B is where you type values. Every field is an Excel defined name referenced by formulas throughout the workbook — you are not editing formulas, only these cells.

| Cell | Defined name | What it means | Dec's actual value (reference only) |
|---|---|---|---|
| B2 | `ContractLabel` | Free-text book label, e.g. "March 2027" | `TEMPLATE` (placeholder — must change) |
| B3 | `ZLContractMonth` | ZL (soybean oil) contract month code | `TEMPLATE` (placeholder — must change) |
| B4 | `HOContractMonth` | HO (heating oil) contract month code | `TEMPLATE` (placeholder — must change) |
| B7 | `HOGalPerContract` | HO gallons per futures contract | 42,000 |
| B8 | `ZLMultiplier` | ZL cents→$/gal conversion multiplier | 7.5 |
| B9 | `ZLCentsPerLB` | ZL contract size, cents/lb | 60,000 |
| B11 | `JohansenWindowLen` | Rolling Johansen re-estimation window, trading days | 63 |
| B14 | `ZThreshold_Tier1` | Entry z-score, tier 1 | 2.25 |
| B15 | `ZThreshold_Tier2` | Entry z-score, tier 2 | 2.10 |
| B16 | `ZThreshold_Tier3` | Entry z-score, tier 3 | 1.75 |
| B17 | `ZExitThreshold` | Exit z-score | 0.10 |
| B20 | `SizingWeight_Tier1` | % of size on tier 1 | 25% |
| B21 | `SizingWeight_Tier2` | % of size on tier 2 | 50% |
| B22 | `SizingWeight_Tier3` | % of size on tier 3 | 25% |
| B25 | `EWMA_Lambda` | EWMA volatility decay factor | 0.94 |
| B26 | `ShockMultiplierThreshold` | Vol-shock detection multiplier | 1.25 |
| B27 | `StopLossUSD_Base` | Stop-loss, $ (base, before risk scalar) | -65,000 |
| B28 | `D4Multiplier` | D4 RIN price multiplier | 1.5 |
| B29 | `RiskLevelInput` | Risk-level scalar applied to stop-loss | 1 |

The three contract-identity fields (B2-B4) always start as literal `"TEMPLATE"` text — overwrite them for every new book. The rest default to Dec's actual live values. **Whether to keep Dec's thresholds/window or use month-specific calibrated values is a separate per-month calibration workstream** — don't assume Dec's numbers transfer to another month without that calibration being done first.

The exact source-of-truth for this table is `scripts/config_map.py` (`CONFIG_LAYOUT`) — if a future engine change adds/renames a Config field, that file is authoritative, not this doc.

### Step 3 — Paste price history into `Data`

| Column(s) | Header | Content |
|---|---|---|
| A | Date | |
| B | BOHO | pasted values |
| C | D4 | pasted values |
| E:I | "Settlement Pricing": Date, SBO, HO, BOHO, D4 | pasted values |
| K:N | "Open Pricing": Date, SBO, HO, BOHO | pasted values |
| S:T | small reference block echoing Config (ZL cents/lb, ZL multiplier, ZL gal, HO gal) | formulas, already present — don't touch |

Same convention as the Dec workbook: paste starting row 2. Columns B/C and the E:N blocks are pasted *values* (not formulas) for that month's history.

### Step 4 — Leave the engine sheets alone
`DiffLag`, `Matrices`, `Johansen`, `Monthly Beta`, `Position Model`, `Results` recalculate automatically off `Data` + `Config`. No formulas to touch.

### Step 5 — The recurring manual step, every month going forward
On `Johansen_Monthly`, append a new row to columns **F, G, H, I**.

**⚠ Known documentation bug:** the workbook's own `Notes` sheet describes this step as "Date in F, EndRow in G" — that is wrong. The actual generated column order (verified against `scripts/build_johansen_monthly.py`) is:

| Column | Header (row 2) | What to enter |
|---|---|---|
| F | EndRow | The `DiffLag` row number corresponding to that month's end |
| G | Date | That month-end's date |
| H | BOHO_Weight | Read off `Johansen_Monthly!C2` at month-end |
| I | D4_Weight | Read off `Johansen_Monthly!D2` at month-end |

Always trust the actual column headers in row 2 of the sheet over the `Notes` sheet prose — this mismatch hasn't been fixed yet (fixing the `Notes` sheet text itself is a small, safe follow-up). `Position Model`'s spread construction looks up the prior month's locked weights from this log; skip this step and that month won't get new positions computed.

## 4. Regenerating the template (only if the engine itself changes)

If a defect in the underlying engine is fixed, the fix goes into the Python build scripts in `scripts/`, then:
```bash
cd scripts && py build_template.py
```
regenerates `Johansen_Template_Engine.xlsx` from the live Dec source. Re-validate afterward:
```bash
cd scripts && py -m pytest tests/ -v   # ~10-15 min, drives real Excel via COM
```
before using the regenerated template to start any new month's book. Never do this against `Johansen_FM_BOHO_D4_Strategy.xlsx` itself — it is read-only input, never a build target.

## 5. Before trusting a new month's numbers — read this

The template has known, **unfixed** defects that matter directly here. Full detail and fix approach: `docs/superpowers/HANDOFF.md`'s "Known limitations" section and the plan doc's (`docs/superpowers/plans/2026-08-05-johansen-fixed-month-template.md`) "Known limitations" section at the end. Summary:

1. **Most consequential:** roughly 30 `Position Model` cells (the headline "RA 2021 Sharpe"–"RA 2026 Sharpe" cells, `DF33:DF38`, and others — `DE46`, `DF48/49`, `DG44/45/48`, `DH44/45/48`, `DF2-5/8-17/20-22/27-29`, `DT3-5`, `DO10`) still hardcode December's specific historical row boundaries. They compute the right numbers for a Dec-replay but will silently compute **wrong** (not erroring, just plausible-looking incorrect) numbers for any other month's summary/Sharpe/PnL-breakdown panel.
2. ~20 cells in the headline summary panel currently show `#N/A` regardless of month (fixable with `AGGREGATE(...,6,...)` or an `IFERROR`-guarded range start — not yet done).
3. Minor: `BZ1:CC1` headers still say "24-26" after being redefined to since-inception accumulators; a few label/exclusion inconsistencies in the validation harness.

**Recommendation:** fix at least item 1 before using the headline summary panel on a real trading book for a new month — everything upstream of that panel (positions, per-day PnL, hedge ratios, z-scores) is solid and validated; it's specifically the hardcoded-row summary/Sharpe cells that are risky for a non-December month.
