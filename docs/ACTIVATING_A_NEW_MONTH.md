# How to Activate a New Fixed-Month BOHO/D4 Book

**Last updated:** 2026-08-10

This is the operational reference for activating a specific contract month (March, July, etc.) in the multi-month consolidated workbook `Johansen_MultiMonth_Template_Engine.xlsx`. For the engineering/build-pipeline side (how the template is generated, known defects, how to fix them), see `docs/superpowers/HANDOFF.md` instead — this doc is "how do I use it," that one is "how does it work / what's still broken."

## 2. The template's 15 sheets, in order

`Notes → Config → Data → DiffLag → Matrices_Johansen_Results → Johansen_Monthly → Monthly Beta → Position Model - January → Position Model - March → Position Model - May → Position Model - July → Position Model - August → Position Model - September → Position Model - October → Position Model - December`

**You only ever touch `Config` and `Data` directly, plus one recurring manual log entry on `Johansen_Monthly`.** Everything else recalculates automatically off those inputs — never hand-edit engine-sheet formulas in a live book; a structural fix belongs in the template scripts, not a one-off patch in an instantiated book. The 8 separate `Position Model - <Month>` tabs (January through December) are each month's independent position-tracking engine; the combined `Matrices_Johansen_Results` tab holds all 8 months' Johansen cointegration analysis and statistics stacked side-by-side.

## 3. Step-by-step: activating a new month

### Step 1 — No Save As needed
Unlike the old single-month-per-file workflow, you do **not** create a new file. One workbook handles all 8 contract months at once. Just open `Johansen_MultiMonth_Template_Engine.xlsx` (or its live counterpart `Johansen_BOHO_D4_Strategy_AllMonths.xlsx` once months are migrated into it).

### Step 2 — Fill in that month's `Config` column
The `Config` sheet has one column per contract month. The month-to-column mapping is the authoritative source in `scripts/config_map.py` (`CONFIG_MONTH_COLUMNS`):

| Month | Column |
|---|---|
| January | B |
| March | C |
| May | D |
| July | E |
| August | F |
| September | G |
| October | H |
| December | I |

Each month's column has the same rows (2-29) and the same field definitions as the old single-month template:

| Row | Field name | What it means | Dec's actual value (reference only) |
|---|---|---|---|
| 2 | `ContractLabel` | Free-text book label, e.g. "March 2027" | `TEMPLATE` (placeholder — must change) |
| 3 | `ZLContractMonth` | ZL (soybean oil) contract month code | `TEMPLATE` (placeholder — must change) |
| 4 | `HOContractMonth` | HO (heating oil) contract month code | `TEMPLATE` (placeholder — must change) |
| 7 | `HOGalPerContract` | HO gallons per futures contract | 42,000 |
| 8 | `ZLMultiplier` | ZL cents→$/gal conversion multiplier | 7.5 |
| 9 | `ZLCentsPerLB` | ZL contract size, cents/lb | 60,000 |
| 11 | `JohansenWindowLen` | Rolling Johansen re-estimation window, trading days | 63 |
| 14 | `ZThreshold_Tier1` | Entry z-score, tier 1 | 2.25 |
| 15 | `ZThreshold_Tier2` | Entry z-score, tier 2 | 2.10 |
| 16 | `ZThreshold_Tier3` | Entry z-score, tier 3 | 1.75 |
| 17 | `ZExitThreshold` | Exit z-score | 0.10 |
| 20 | `SizingWeight_Tier1` | % of size on tier 1 | 25% |
| 21 | `SizingWeight_Tier2` | % of size on tier 2 | 50% |
| 22 | `SizingWeight_Tier3` | % of size on tier 3 | 25% |
| 25 | `EWMA_Lambda` | EWMA volatility decay factor | 0.94 |
| 26 | `ShockMultiplierThreshold` | Vol-shock detection multiplier | 1.25 |
| 27 | `StopLossUSD_Base` | Stop-loss, $ (base, before risk scalar) | -65,000 |
| 28 | `D4Multiplier` | D4 RIN price multiplier | 1.5 |
| 29 | `RiskLevelInput` | Risk-level scalar applied to stop-loss | 1 |

The three contract-identity fields (rows 2-4) always start as `"TEMPLATE"` text — overwrite them with that month's actual contract codes. The rest default to Dec's actual live values. **Whether to keep Dec's thresholds/window or use month-specific calibrated values is a separate per-month calibration workstream** — don't assume Dec's numbers transfer to another month without that calibration being done first.

The exact source-of-truth for this layout is `scripts/config_map.py` (`CONFIG_FIELDS`) — if a future engine change adds/renames a Config field, that file is authoritative, not this doc.

### Step 3 — Paste that month's price history into the `Data` sheet's corresponding block

The `Data` sheet has one 20-column-wide block per contract month, stacked horizontally with a 2-column gap between each block. To find where to paste that month's data, compute the column offset: `multi_month.column_offset("<MonthName>", DATA_BLOCK_WIDTH=20, GAP=2)` (both functions are in `scripts/multi_month.py`).

For reference, each month's block starts at these columns:

| Month | Starting column |
|---|---|
| January | A (offset 0) |
| March | V (offset 22) |
| May | AO (offset 44) |
| July | BH (offset 66) |
| August | CA (offset 88) |
| September | BT (offset 110) |
| October | EM (offset 132) |
| December | FP (offset 154) |

Within each month's 20-column block, the structure is the same as the old single-month template's `Data` sheet:

| Column(s) | Header | Content |
|---|---|---|
| (block start) | Date | |
| +1 | BOHO | pasted values |
| +2 | D4 | pasted values |
| +4:+8 | "Settlement Pricing": Date, SBO, HO, BOHO, D4 | pasted values |
| +10:+13 | "Open Pricing": Date, SBO, HO, BOHO | pasted values |
| +18:+19 | small reference block echoing Config (ZL cents/lb, ZL multiplier, ZL gal, HO gal) | formulas, already present — don't touch |

Same convention as the Dec workbook: paste starting at row 2 within each month's block. Columns B/C and the E:N blocks are pasted *values* (not formulas) for that month's history.

### Step 4 — Leave the engine sheets alone
`DiffLag`, `Matrices_Johansen_Results`, `Monthly Beta`, and all 8 `Position Model - <Month>` tabs recalculate automatically off `Data` + `Config`. No formulas to touch.

### Step 5 — The recurring manual step, every month going forward
On `Johansen_Monthly`, append a new row to that month's 11-column block (columns F, G, H, I, ... in the January block, columns X, Y, Z, AA, ... in the March block, etc. — same offset pattern as the `Data` sheet).

**⚠ Known documentation bug:** the workbook's own `Notes` sheet describes this step as "Date in F, EndRow in G" — that is wrong. The actual generated column order (verified against `scripts/build_johansen_monthly.py`) is:

Within each month's 11-column block on `Johansen_Monthly`, the structure is:

| Column(s) | Header (row 2) | What to enter |
|---|---|---|
| first | EndRow | The `DiffLag` row number corresponding to that month's end |
| +1 | Date | That month-end's date |
| +2 | BOHO_Weight | Read off that month's `Johansen_Monthly!<month-block-col+2>2` at month-end |
| +3 | D4_Weight | Read off that month's `Johansen_Monthly!<month-block-col+3>2` at month-end |

Always trust the actual column headers in row 2 of the sheet over the `Notes` sheet prose — this mismatch hasn't been fixed yet (fixing the `Notes` sheet text itself is a small, safe follow-up). `Position Model`'s spread construction looks up the prior month's locked weights from this log; skip this step and that month won't get new positions computed.

## 4. Regenerating the template (only if the engine itself changes)

If a defect in the underlying engine is fixed, the fix goes into the Python build scripts in `scripts/`, then:
```bash
cd scripts && py build_template.py
```
regenerates `Johansen_MultiMonth_Template_Engine.xlsx` from the live Dec source. Re-validate afterward:
```bash
cd scripts && py -m pytest tests/ -v   # ~10-15 min, drives real Excel via COM
```
before using the regenerated template to start any new month's book. Never do this against `Johansen_FM_BOHO_D4_Strategy.xlsx` itself — it is read-only input, never a build target.

## 5. Before trusting a new month's numbers — read this

The template has known, **unfixed** defects that matter directly here. Full detail and fix approach: `docs/superpowers/HANDOFF.md`'s "Known limitations" section and the plan doc's (`docs/superpowers/plans/2026-08-06-johansen-multi-month-consolidation.md`) "Known limitations" section at the end. Summary:

All four issues below now apply **independently to each of the 8 `Position Model - <Month>` tabs** (one per contract month), not hidden across 8 separate files. None were fixed by the consolidation — they're just relocated and now visible as separate instances:

1. **Most consequential:** roughly 30 cells in each `Position Model - <Month>` tab (the headline "RA 2021 Sharpe"–"RA 2026 Sharpe" cells and others) still hardcode that month's specific historical row boundaries. They compute the right numbers for their month's replay but will silently compute **wrong** (not erroring, just plausible-looking incorrect) numbers if a new month is added or row boundaries shift.
2. ~20 cells in each headline summary panel currently show `#N/A` (fixable with `AGGREGATE(...,6,...)` or an `IFERROR`-guarded range start — not yet done).
3. Minor: header inconsistencies and a few label/exclusion mismatches in each tab.
4. Minor: validation harness blind spots.

**Recommendation:** fix at least item 1 before using the headline summary panel on a real trading book for any month — everything upstream of that panel (positions, per-day PnL, hedge ratios, z-scores) is solid and validated; it's specifically the hardcoded-row summary/Sharpe cells that are risky.
